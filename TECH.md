## Backend

| Параметр | Значення |
|---|---|
| Мова програмування | Python |
| Фреймворк | FastAPI |
| База даних | PostgreSQL |
| ORM / драйвер | SQLAlchemy (ORM, sync) + Alembic (міграції), psycopg |
| Автентифікація | JWT у httpOnly cookie (PyJWT), хешування паролів argon2 (argon2-cffi) |
| Документація API | OpenAPI / Swagger UI |

**Чому обрали:** 

1. **Python + FastAPI:** вибір мови та фреймворку обґрунтований переважно попереднім досвідом команди
2. **PostgreSQL:** архітектура проєкту потребує реляційної бази даних. Тут є зв'язки «один до багатьох» (наприклад, один тест має багато питань) і «багато до багатьох» (кожен користувач може проходити декілька тестів, і кожен тест може проходитися декількома користувачами). Окрім того, PostgreSQL добре інтегрується з SQLAlchemy та Alembic
3. **SQLAlchemy (sync) + Alembic, psycopg 3:** обрано синхронний підхід, оскільки він простіший і легше піддається покриттю тестами. Проєкт має навчальний характер, тому великого навантаження на БД не очікується, а отже, значущої різниці порівняно з асинхронним підходом не буде
4. **JWT у httpOnly cookie, argon2:** ТЗ прямо вимагає: «Токен передається клієнту через httpOnly cookie. Всі захищені кінцеві точки (endpoint) читають токен з cookie, не з Authorization header». Argon2 є одним із найсучасніших алгоритмів хешування паролів і рекомендується OWASP
5. **OpenAPI / Swagger UI:** FastAPI автоматично генерує OpenAPI-документацію, а Swagger UI доступний за адресою /docs
